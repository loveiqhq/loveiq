# features/admin/server/

Admin-only server code. Since 16 Oct 2026 the admin is AP-Analytics only, and the modules only the old admin pages used were removed. What is left serves AP, the remaining admin API routes, the Slack digest crons and the company brain.

## What belongs here

- Auth and role checks for the admin surface
- Supabase helpers for admin route handlers and server components
- AP-Analytics' figures under `ap/`
- Builders the digest crons and the brain import
- Admin transactional email templates under `emails/`

## What does not belong here

- Route handlers: use [`app/api/admin/AGENT_README.md`](../../../app/api/admin/AGENT_README.md)
- Admin UI composition: use [`features/admin/ui/AGENT_README.md`](../ui/AGENT_README.md)
- Global utilities shared outside admin: use [`shared/AGENT_README.md`](../../../shared/AGENT_README.md)

## Key entry files

- `auth.ts`: `verifyAdminSession()`, the session gate every signed-in admin route uses (AP's through `ap/route-guard.ts`)
- `statistics.ts`: shared stats primitives used by AP's traffic page, the conversion digest, the A/B readouts and the brain
- `experiment-readouts.ts`: the A/B readouts behind the brain's `experiments` tool (the old admin's A/B overview used them until 16 Oct 2026). The team's test runs are left out: an @loveiq.org address (`isStaffEmail`, the rule that sets `payment.is_test`, as the digests' funnel functions do since migration `20261006230000`) or an account that redeemed the team's test coupon (`ap/team.ts`, the `ap_team_user` view AP-Analytics counts by; Jarvis's chapter votes and user totals leave them out too); a sale is a succeeded, non-test payment above €0, counted at what was paid. The file explains the window each test is read over
- `ap/`: AP-Analytics (`/admin/ap`): `facts.ts` reads `ap_facts` (`fetchFactsFor` also marks each reader new or returning, through `posthog.ts` `markVisitors`, when the New & returning filter is set), `metrics.ts` and `filters.ts` count and slice it, one builder per page (`focus.ts` for the Dashboard, `assessment.ts`, `traffic.ts` with its arithmetic in `traffic-math.ts`, `landing.ts`, `survey-page.ts`, `report-page.ts`, which also reads `ap_report_extras` and, for the guided tour from `TOUR_TRACKING_FROM`, `ap_report_tour`, `payment.ts`; `survey.ts` reads `ap_survey_steps` and `get_survey_dropoff_runs` (each question order's funnel: the runs begun in the range, each walked in the order it was asked and counted up to the furthest question it reached, so no question has more than the one before; a leading email question, asked first until 16 Aug 2026, isn't how far a run got; a question first asked after the range isn't listed), `answers.ts` reads `ap_question_answers`), `common.ts` for what the pages share, `ads.ts` for Google Ads per campaign and keyword, `google-live.ts` for the Google Analytics, Ads and Search Console tables the catalog and explorer read live, `pay-to-start.ts` for the Pay to start page (whose `payToStartFor` the Dashboard's funnel comparison and the Landing page's pay-to-start table reuse, so their figures agree), `posthog.ts` for what only PostHog sees, `catalog.ts` and `explorer.ts` for the data catalog and the masked raw data explorer, `route-guard.ts` for `apGuard`, `team.ts` for the team's accounts (the `ap_team_user` view: an @loveiq.org address, or an account that redeemed the team's 100% test code), which every reader, page and info card leaves out. A payment is dated by when it was paid (`payment_date_time`), not when its row was written (a pay-to-start purchase's row is written when its survey claims it). Checkout success counts the report's checkouts only: pay to start's own are on its page. A run that leaves the questions by walking back with the browser's Back is placed where the walk began, and those Backs are no Went back; the intro's Backs count only before question 1. Under "Free survey" the ad spend shows when no ad of the range landed on a pay-to-start page (`pay-to-start.ts` `freeAdsOnly`), and the EUR 1.99 figures are blank while the report's own gate is off and the free survey sold none (`common.ts` `freePreBlocked`).
